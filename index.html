📚 Cache Memory Concepts & Formulas Guide

Learn how CPU memory addresses are mapped to cache lines and calculate bit lengths interactively.

🧮 Interactive Address Bit Field Calculator

🎯 Direct Mapping

Each main memory block maps to exactly one specific cache line based on the set index calculation.

Cache Line Index = (Memory Block Address) mod (Total Cache Lines)
  • Block Address: Math.floor(Address / Block Size)
  • Offset Bits: log₂ (Block Size)
  • Index Bits: log₂ (Total Lines)
  • Tag Bits: Address Width - Index Bits - Offset Bits

🔀 Set-Associative Mapping

Cache is divided into sets, each set containing N lines. A memory block can be placed in any line within its designated set.

Set Index = (Memory Block Address) mod (Total Sets)
  • Total Sets: Total Lines / N (where N is associativity)
  • Index Bits: log₂ (Total Sets)
  • Tag Bits: Address Width - Index Bits - Offset Bits
  • Replacement: LRU / FIFO algorithms manage line evicted when set is full.

🌐 Fully Associative Mapping

A memory block can be loaded into any available line in the entire cache memory without set constraints.

No Set Index Field! (Index Bits = 0)
  • Sets: 1 single global set containing all cache lines
  • Offset Bits: log₂ (Block Size)
  • Tag Bits: Address Width - Offset Bits
  • Search: Requires searching all tags in parallel (content-addressable memory).

⚡ Cache Hit vs Cache Miss

  • Cache Hit: Requested address tag is present in the cache and valid bit is 1. CPU reads data instantly.
  • Compulsory Miss (Cold Miss): First access to a memory block. Block must be fetched from main memory.
  • Conflict Miss: Multiple blocks map to the same set and evict each other (in Direct/Set Associative).
  • Capacity Miss: Cache is full and cannot contain all blocks needed during program execution.
